## 更新 35 · 独立语音转文字 API
- 设置新增“语音转文字”独立配置页，与聊天 AI 主 API / 副 API 分开保存。
- 支持 OpenAI-compatible STT：Base URL、API Key、识别模型、语言、提示词。
- 支持通过 `/models` 拉取模型列表并从弹层选择识别模型。

- 长按没有转写的语音消息选择“转文字”时，会按当前 STT 配置即时识别；失败后仍可重试。
- 未配置 STT 时保留浏览器原生 SpeechRecognition 作为可选兜底。

### 本版语音
- “按住说话”使用浏览器原生麦克风与 MediaRecorder 在本地录音。
- 松开发送；按住时向上滑动可取消。
- 录音消息以 Blob 形式保存在 IndexedDB，不依赖后端。
- 点击语音气泡即可本地播放。


## 更新 34 · 语音消息 AI 上下文
- 真实录音：录音过程中自动尝试使用浏览器 SpeechRecognition / webkitSpeechRecognition 获取隐藏转写结果，并把结果写入消息的 `transcript` / `aiTranscript` 字段。
- AI 回复时：真实语音和无声语音都不再只传 `[语音消息]` 占位文本；有转写内容时，会自动作为用户消息上下文喂给 AI，用户不需要手动点“转文字”。
- 无声语音：发送时编辑的文字同时保留为隐藏 AI 上下文，因此无论用户是否在界面上展开“转文字”，AI 都能直接知道内容。
- 若浏览器不提供语音识别能力，真实录音仍会正常发送和播放，但本地版本无法凭空获得语音文字；此时需要后续接入独立 STT API 作为兜底。


## 聊天消息类名（v1.40 基础样式）

后续聊天界面美化建议优先使用下面这组 `chat-*` 类名；原有 `pm-*` 类名暂时保留，作为兼容层，不建议后续主题直接依赖。

- `chat-message`：整条消息行
- `chat-message--sent`：我方消息
- `chat-message--received`：对方消息
- `chat-message--voice`：语音消息行
- `chat-message__avatar`：消息头像
- `chat-message__content`：消息主体容器
- `chat-message__content--voice`：语音主体容器
- `chat-bubble`：所有聊天气泡的基础类
- `chat-bubble--text`：文字气泡
- `chat-bubble--voice`：语音气泡
- 语音气泡宽度会随时长自然增长，范围约 74–200px。
- `chat-bubble--sticker`：表情包气泡
- `chat-message__transcript`：语音转写文字

### 当前气泡基础规格

我方：`#95EC69` / 文字 `#000000`
对方：`#FFFFFF` / 文字 `#000000`
圆角：`4px`


## 更新 42 · 文字气泡换行
- 普通文字气泡最大宽度调整为 72%。
- 多行中文/中英混合文字启用两端对齐，尽量让换行后的左右边缘视觉一致。
- 英文继续按完整单词换行，不使用自动断词。
- 单行气泡保持普通左对齐，避免短文本被拉伸。

- v7：语音转文字气泡复用普通文字气泡的多行对齐逻辑；中文多行两端对齐，英文保持完整单词换行并让末行自然靠左。

### 私聊「文件」功能（v15）
加号菜单中的「文件」会调用手机系统文件选择器。选中文件后会以文件卡片发送到当前 Char；TXT、Markdown、JSON、CSV、代码/配置类文本以及 DOCX 会提取正文并注入后续 AI 对话上下文，其它文件保留文件名、类型和大小等元数据，不虚构未读取到的正文。

## 更新 43 · 聊天记忆页与副 API 短期记忆
- 加号菜单移除“更多”功能项。
- 加号菜单“记忆”进入独立记忆页，可自定义最近消息上下文深度与短期记忆自动总结触发条数。
- 短期记忆总结固定使用设置中的副 API，不占用主聊天 API。
- 旧消息超出上下文深度且达到触发阈值后，会自动由副 API 总结为短期记忆；主 AI 后续请求只携带短期记忆 + 最近上下文消息。
- 支持在记忆页手动立即总结与清空当前聊天的短期记忆；清空不会删除原始聊天记录。


## 更新 44 · 全消息类型上下文与总结状态弹窗
- 主 AI 上下文现在明确纳入聊天界面的全部消息类型：普通文字、语音/转写、文件正文、真实/虚拟位置、图片与表情包；图片与表情包在主 AI 请求中以多模态 image_url 形式发送（模型支持视觉时可直接读取图像）。
- 短期记忆总结源同样覆盖全部消息类型；对没有图像本体或可靠语音转写的内容，不猜测未知细节。
- 手动“立即总结当前聊天”彻底绕过自动总结条数阈值，只要存在未总结消息就可以立即总结。
- 总结过程中显示居中的状态弹窗“正在总结”；成功显示完成信息；失败显示副 API 返回的具体错误原因。
